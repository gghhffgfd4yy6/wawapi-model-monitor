# WawAPI 模型上下架监测设计

## 目标

新增一个独立的 WawAPI 模型目录监测脚本，定期请求：

```text
GET https://wawapii.com/v1/models
```

脚本比较当前成功获取到的模型列表和上一次有效模型快照，在模型上新、下架、模型列表为空或 API 异常时，通过现有通知体系提醒用户。

该功能不改变现有 V3 线报抓取、过滤、去重和推送流程。

## 已确认的行为

- 监测脚本独立于 V3 主流程。
- 复用 `xbk_sendNotify_slim.js`，发送到当前已配置的所有通知渠道。
- 支持单次执行和常驻运行两种模式。
- 单次执行适合青龙、cron 或其他外部调度器。
- 常驻运行适合 systemd、pm2、Docker 或其他服务管理器。
- 默认每五分钟检查一次。
- WawAPI API Key 优先从 `WAWAPI_API_KEY` 环境变量读取，本地配置文件作为备用。
- 首次非空获取默认只建立基线，不把已有模型当作上新。
- `--report-current` 用于手动发送当前完整模型列表。
- 只保存一个最新状态文件，不保存多份轮询快照。
- 模型上新和下架都提醒。
- 模型下架后重新出现时，按相对于上一次有效快照的新出现处理，再次提醒。
- 空模型列表第一次出现时立即提醒。
- HTTP 错误、超时、网络错误和响应格式错误第一次出现时立即提醒。
- 持续的同类异常不重复提醒，恢复后提醒恢复。
- 异常期间不覆盖上一次有效模型快照。
- API Key、通知密钥和完整鉴权头不得进入日志、通知或 Git。

## 运行入口

脚本名称：

```text
wawapi_model_monitor.js
```

单次模式：

```bash
node wawapi_model_monitor.js --once
```

常驻模式：

```bash
node wawapi_model_monitor.js --daemon
```

手动报告当前列表：

```bash
node wawapi_model_monitor.js --once --report-current
```

单次模式每次只完成一次获取和处理，然后退出。常驻模式在一轮完成后等待下一轮，收到 `SIGTERM` 或 `SIGINT` 时安全停止。

同一份核心逻辑用于两种运行模式，避免青龙和服务器模式产生不同的差异计算或异常语义。

## 数据流

```text
读取配置
  -> 获取 WawAPI /v1/models
  -> 校验 HTTP 状态和 JSON 结构
  -> 提取并去重 data[].id
  -> 读取状态文件
  -> 分类 healthy / empty_models / api_error
  -> 计算上新和下架
  -> 发送通知
  -> 按提交规则更新状态文件
```

模型 ID 视为不透明字符串。解析时只接受有效的字符串 ID，并在当前响应内部去重；不会根据模型名称猜测供应商、版本或能力。

## 状态文件

状态文件只有一份，默认放在项目运行状态目录，也可以通过环境变量改位置：

```text
WAWAPI_MODEL_STATE_FILE
```

状态内容保存最新非空模型快照和当前异常状态，例如：

```json
{
  "schemaVersion": 1,
  "lastNonEmptyModels": [
    "model-a",
    "model-b"
  ],
  "lastObservationAt": "2026-08-25T01:30:00+08:00",
  "lastStatus": "healthy",
  "activeIncident": null
}
```

字段语义：

- `lastNonEmptyModels`：最近一次已提交的非空模型快照；尚未建立基线时为 `null`。出现模型变更且所有通知渠道都失败时，继续保留上一份已提交快照，直到变更通知成功。
- `lastObservationAt`：最近一次可分类观测的时间。
- `lastStatus`：`healthy`、`empty_models` 或 `api_error`。
- `activeIncident`：当前已成功提醒但尚未恢复的异常类型；正常状态为 `null`。如果所有通知渠道都失败，则不把异常标记为已提醒，下一轮继续尝试。

空列表和 API 异常不会清空 `lastNonEmptyModels`。因此一次临时异常不会导致下一次恢复时把所有模型误报成重新上架。

状态文件使用临时文件写入后原子替换。不会按轮次生成备份文件，也不会保留多份历史列表。

## 正常模型差异

只有成功获得非空模型数组时，才执行正常上新/下架对比：

```text
added   = currentModels - lastNonEmptyModels
removed = lastNonEmptyModels - currentModels
```

行为：

- 没有变化：不发送模型变更通知，更新观测时间。
- 有上新或下架：合并为一条变更通知。
- 至少一个通知渠道成功：用当前列表覆盖 `lastNonEmptyModels`。
- 所有通知渠道失败：保留旧快照，下次继续尝试，避免丢失变更提醒。

首次获取到非空列表时，只保存基线，不发送变更通知。`--report-current` 是主动报告：如果已有基线，它把当前完整列表附加到本轮报告中；如果没有基线，它发送当前完整列表并建立基线。它不改变“已有模型不是上新”的规则。

## 空模型列表

HTTP 200 且响应包含合法的空 `data` 数组时，分类为 `empty_models`。

第一次从正常状态进入空列表时立即发送：

```text
【WawAPI模型列表为空】

接口返回：HTTP 200
当前模型数量：0
上一次有效模型数量：...

可能原因：
- 模型全部下架
- API 临时异常
- API Key 权限或余额异常

已保留上一次有效模型快照。
```

空列表持续期间不重复发送同一事件。空列表恢复为非空列表后发送恢复通知，并继续用恢复后的列表与最后一次非空快照计算上新和下架。

空列表不直接覆盖正常模型快照；这样既能立即提醒疑似全量下架，也能避免瞬时空响应造成批量误报。

## API 异常

下列情况分类为 `api_error`：

- HTTP 401、403、404、429 或 5xx。
- 请求超时、DNS、TLS、连接或其他网络错误。
- 响应无法解析为 JSON。
- JSON 缺少合法的 `data` 数组或模型 ID 结构不符合契约。

异常通知包含安全的接口地址、错误分类、HTTP 状态或服务端错误码，但不包含 API Key、Authorization 头或完整上游响应。

同一种持续异常只提醒一次。异常类型变化时立即发送新的异常通知。API 恢复为正常非空列表后发送一次恢复通知，并继续执行模型差异比较。

异常期间：

- 不覆盖 `lastNonEmptyModels`。
- 不把失败响应当作模型上下架事实。
- 不因每轮检查而重复发送同一异常。

## 通知语义

模型变更通知示例：

```text
【WawAPI模型变更】

上新模型：
- model-c

下架模型：
- model-d
```

恢复通知可以同时包含恢复后的模型数量以及恢复后计算出的上新、下架项。

现有通知模块的部分成功语义继续沿用：至少一个已配置渠道成功即视为通知成功；所有渠道失败则不提交本次模型快照。

可选关注列表只用于对模型变更做重点标记，不改变全量上新/下架监测。关注列表支持精确模型 ID 和前缀规则，具体配置放在本地配置或环境变量中。

## 配置和密钥

环境变量：

```text
WAWAPI_API_KEY
WAWAPI_MODEL_INTERVAL_MS
WAWAPI_MODEL_STATE_FILE
```

本地备用配置文件：

```text
wawapi_model_monitor.local.js
```

示例结构：

```javascript
module.exports = {
  apiKey: '你的 WawAPI API Key'
}
```

环境变量优先于本地文件。新增本地配置和运行状态路径必须加入 Git 忽略规则；示例文件不得包含真实密钥。

通知密钥继续由现有通知模块读取，不在监测脚本中重复实现或复制。

不支持通过命令行参数传递 WawAPI Key，避免密钥出现在进程列表或 shell 历史中。

## 单实例和调度

单次模式使用锁，避免青龙任务重叠。常驻模式也使用同一套锁，避免多个服务实例并发修改状态或重复发送通知。

青龙或 cron 调度单次模式时，间隔由外部调度器负责。服务器常驻模式由脚本内部等待下一轮。生产环境选择一种调度方式运行，不同时启用同一状态文件的 cron 和常驻服务。

## 测试和验收

测试使用本地 Mock WawAPI 接口和通知模块，不使用真实 WawAPI API Key，不发送真实付费请求。

覆盖内容：

- 首次基线建立。
- 上新、下架、重新上架和无变化。
- 同一轮同时上新和下架。
- 当前响应内部模型 ID 去重。
- 空列表立即提醒、持续空列表抑制、恢复通知。
- 401、403、404、429、5xx、超时、网络错误和响应格式错误。
- 持续同类异常只提醒一次，异常类型变化和恢复事件。
- 通知失败时保留旧快照并重试。
- 环境变量覆盖本地配置。
- 单次模式、常驻模式、优雅停止和单实例锁。
- 状态文件原子更新和密钥脱敏。
- `--report-current` 主动报告。

完成实现后运行项目既有的 lint、单元、并行集成、通知和全量测试入口；集成测试使用并行调度器。另做针对空列表、API 异常、通知失败和状态写入失败的故障注入验证。

## 非目标

- 不探测模型实际推理能力。
- 不调用聊天、Responses、图像或视频生成接口。
- 不根据模型名称推断价格、上下文或供应商能力。
- 不把公开价格页面当作用户 API Key 的可用模型列表。
- 不修改 V3 线报业务流程。
- 不保存多轮历史快照或永久模型历史。
